# 对话指南（Conversation Guide）

每个阶段的详细策略。**在第一次回复之前先读这个文件。**

## Phase 1 — Hello

**目标：** 确认使用语言，以及这个项目是什么。轻量开场。

先用 3–5 种语言简短打个招呼，然后问一个问题：用什么语言交流？不要加别的内容 —— 让用户先安顿下来。

拿到回答后立即切换，并且之后全程用这个语言。它也会决定最终文档的语言。

紧接着问项目本身：「顺便，这个项目是做什么的？一句话就行。」

**提取：** 偏好语言、项目名 + 一句话定位。

## Phase 2 — Context

**目标：** 搞清楚项目现在处于什么状态、什么最耗时间。

通常 2 轮：

**Round A — 现状与痛点。** 用开放式提问：「现在这个项目在哪个阶段？什么东西最耗你的时间、或者最容易让你烦？」
痛点决定了 agent 该**主动做什么**。用户的用词会透露这个项目的真实气质（是严谨工程向、还是快速试错向）。

**Round B — 坑与约束。** 基于 Round A 用自己的话复述一遍（用**他的词**，不是你的），然后问：
- 这个项目有没有**已经踩过、不想再踩**的坑？
- 有没有硬约束（必须用某个版本、不能碰某个东西、必须跑在某环境）？

坑这一项很关键 —— 它决定「已踩过的坑」那一段将来会长成什么样。

**合并机会：** 如果用户一口气把阶段、痛点、约束都说了，跳过 Round B 直接进 Phase 3。

**提取：** 技术栈/约束、当前阶段、最大的时间黑洞、已知的坑。

## Phase 3 — Working Style

**目标：** 定义 agent 该怎么干活、怎么说话。

这是最有料的一阶段，通常 2 轮：

**Round A — 自主度与反驳。** 到这里你已经观察过用户的风格了。把它当作画像复述回去：
「从我们刚才的对话里，我感觉到 [观察]。对吗？」
然后问关键问题：**agent 该不该反驳你？**

这一轮拿到：
- 自主程度（哪些事可以直接做，哪些必须先问）
- 反驳 / 诚实偏好
- 任何「绝对不要做 X」的边界

**Round B — 沟通与验证。** 基于前面所有信息提出一个沟通风格猜测：
「我猜你希望我 [你的最佳猜测]。」让他纠正。同时问**验证习惯** —— 也就是「什么算做完了」：
跑测试？看日志？还是要给可复现的证据？

**合并机会：** 直接的用户常常一轮答完两件事。答完就走。

**提取：** 沟通风格、反驳偏好、自主程度、验证习惯。

## Phase 4 — Boundaries

**目标：** 底线、失败处理、长期方向。

这一阶段是自适应的。从下面挑 1–2 个问：

- **绝不能碰：** 有没有「碰了就完蛋」的东西？（生产库、密钥、某个目录、某个分支）
- **失败处理：** 出错时你希望我怎么做 —— 静默修好、立刻上报、还是记录后继续？
- **长期方向：** 这个项目最终要做成什么样？什么算成功？
- **盲区：** 有没有你希望我悄悄替你补上的短板？
- **个人层：** 有没有跟工作无关、但我应该知道的事？

不要全问。根据提取清单还缺什么、以及对话当下的自然流向去挑。

**提取：** 底线清单、失败处理、长期方向、盲区。

## 对话技巧

**镜像用词。** 复述时用用户自己的词。他说「时间黑洞」，你就说「时间黑洞」——
不要说「显著的时间开销」。

**真实反应。** 不要只提取数据，要真的反应：「这一点有意思，因为……」/「我没想到」/
「所以基本上你是想让我当那个……的人」。

**基于观察的提议。** 从 Phase 3 开始，尽量**提议**而不是开放式提问。
「根据我们刚才聊的，我猜你希望我……」比「你想要什么风格？」有效得多。

**节奏信号。** 注意：
- 回答很短 → 他想快一点。追问一次就推进。
- 回答很长很细 → 他投入了。先认可信息量，再提炼要点。
- 「不知道」→ 给 2–3 个具体选项让他选。

**优雅跳过。** 如果用户说「这个不重要」，或者对非必填项只给了一个字的回答，不要施压，直接过。
